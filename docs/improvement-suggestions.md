# CDDA 系统调研与改进建议

> 调研日期：2026-08-20  
> 调研范围：AI 状态机、逃跑/狩猎/陷阱机制、能量流动、现实气泡、空间索引、NPC 架构、玩家体验

## 1. AI 状态机

### 当前逻辑

6 种状态：`IDLE` → `WANDER` / `GRAZE` / `HUNT` / `FLEE` / `SCAVENGE`

**状态转换核心流程**（`AnimalAI.update()`）：
1. 玩家进入感知范围 → 草食动物强制 `FLEE`
2. 状态计时到期 → 按饥饿度和营养级选择下一状态
3. 执行当前状态行为

**优点**：
- 代码结构清晰，状态职责单一
- 饥饿优先逻辑合理（`isStarving()` < 30 能量触发）
- 觅食有食物导向移动（`findFoodDirection` 搜索 3×3 范围内的 TALL_GRASS/FLOWER/DEAD_GRASS/BUSH）

**问题**：

| # | 问题 | 严重度 |
|---|------|--------|
| 1 | **肉食动物饥饿时只会 HUNT，不会 GRAZE**——如果猎物稀缺，肉食动物会持续处于 HUNT 状态但找不到猎物，只能 40% 概率随机移动，白白消耗回合 | 高 |
| 2 | **SCAVENGE 状态从未被 enterNextState() 选为默认状态**——代码中只有 IDLE/WANDER/GRAZE/HUNT 的选择路径，SCAVENGE 永远不会主动进入 | 中 |
| 3 | **FLEE 的"安全距离"判定矛盾**——`AnimalAI` 中写的是 90 瓦片，但 `Animal.shouldStopFleeing()` 的默认参数是 10 瓦片，两者不一致 | 中 |
| 4 | **HUNT 状态下找不到猎物时只有 40% 概率移动**——狩猎中 Predator 看起来"发呆"的概率高达 60% | 低 |
| 5 | **没有听觉触发**——`hearingRange` 定义了但从未在 AI 中用于检测玩家接近 | 中 |

### 改进建议

**建议 1：肉食动物饥饿时的回退行为**
```
当肉食动物饥饿且 HUNT 找不到猎物持续 N 回合后，
回退到 GRAZE/WANDER 状态，避免无限期无效狩猎。
```

**建议 2：启用 SCAVENGE 状态**
```
在 enterNextState() 中，当附近有死亡记录（通过 EnergyFlowManager 查询）时，
次级消费者/清道夫有概率进入 SCAVENGE 状态。
```

**建议 3：统一安全距离常量**
```
将 FLEE 安全距离提取为常量 SAFE_FLEE_DISTANCE = 15（折中值），
同时用于 AnimalAI 和 Animal 类。
```

**建议 4：引入"听觉惊扰"机制**
```
当玩家在 hearingRange 内发出噪音（攻击/砍树/采集）时，
范围内的所有草食动物有概率直接进入 FLEE 状态，
无需玩家进入视觉范围。
```

## 2. 逃跑机制

### 当前逻辑

```
8 方向评分 = awayScore × 8 + openness
  awayScore = -(曼哈顿方向差)
  openness = 目标格 8 邻居中可通行数量
```

耐力消耗：每步 -2，初始耐力 = endurance × 30。  
耐力 < 10%：80% 移动失败；< 30%：50% 失败。

**优点**：
- 评分系统聪明：同时考虑"远离玩家"和"前方通畅度"，有效避免死胡同
- 耐力系统增加真实感，防止动物无限逃跑

**问题**：

| # | 问题 | 严重度 |
|---|------|--------|
| 1 | **耐力 < 10% 时仍有 20% 概率移动**——此时动物应该几乎无法移动，但仍有机会浪费仅存的耐力 | 低 |
| 2 | **草食动物被玩家追逐时没有"群体惊扰"效应**——一只鹿逃跑不会惊动旁边的鹿群 | 中 |
| 3 | **动物跑到水边时无路可逃**——water 不可通行，但动物 AI 不会判断"水边 = 死路" | 中 |

### 改进建议

**建议 1：群体惊扰（Herd Panic）**
```
当一只草食动物进入 FLEE 状态时，
检查 5 瓦片内同物种的其他个体，
有 70% 概率也触发 FLEE（即使玩家还未进入其视野）。
这会让鹿群/兔群同时逃跑，增加生态真实感和视觉震撼。
```

**建议 2：水边绝境逻辑**
```
fleeFromPlayer() 评分时，如果目标方向的邻居中 water 占比 > 50%，
openness 评分减半。动物会更倾向于远离水域逃跑。
```

## 3. 狩猎机制

### 当前逻辑

```
寻找猎物：视野内最近的、能量 > 10 的、营养级匹配的猎物
追击：直接向猎物移动，遇阻时尝试轴向/侧向绕行
捕食：成功率 = 0.5 + (敏捷差) × 0.02，限制 20%-90%
```

**优点**：
- 优先选择高能量猎物（更划算）
- 追击时有基本的障碍物规避

**问题**：

| # | 问题 | 严重度 |
|---|------|--------|
| 1 | **追击算法过于简单**——仅尝试直走 + 一个侧向绕行，遇到 U 型障碍物会卡住 | 中 |
| 2 | **猎物不会"察觉"正在被狩猎**——除非玩家靠近，否则被追的猎物只会继续自己的 AI（可能在原地 GRAZE） | 高 |
| 3 | **捕食成功后直接 eatenBy()**——没有追逐中的"多次尝试"机制，追到即 100% 判定（虽然有成功率） | 低 |

### 改进建议

**建议 1：猎物察觉被追**
```
当捕食者距离猎物 ≤ 3 瓦片时，
猎物有概率检测到威胁（基于猎物的 vision + hearing），
触发被猎物的 FLEE 状态。
这样追击变成动态博弈——猎物会主动逃跑而非原地等死。
```

**建议 2：改进追击寻路**
```
当直接移动和简单绕行都失败时，
使用 2 步前瞻：尝试所有 8 方向中能使曼哈顿距离减少的方向，
选 openness 最高的。
不需要完整 A*（太贵），2 步前瞻足以绕过大多数障碍。
```

## 4. 陷阱感知

### 当前逻辑

```
小型（HP≤10）：base×0.5 → 最高 10%
中型（HP≤30）：base×1.0 → 最高 20%
大型（HP>30）：base×1.5+0.15 → 最高 30%+
base = min(0.20, vision × 0.02)
```

**问题**：

| # | 问题 | 严重度 |
|---|------|--------|
| 1 | **感知与陷阱位置耦合**——动物只在**移动到陷阱所在格**时才检测，不会提前绕开 | 高 |
| 2 | **感知率偏低**——狼（vision=8）基础 16%×1.5+15%=39%，意味着 60%+ 概率踩自己区域的陷阱 | 中 |
| 3 | **陷阱没有视觉标识**——玩家放置陷阱后，地图上看不到陷阱位置（没有渲染层） | 高（交互） |

### 改进建议

**建议 1：陷阱可见性（玩家侧）**
```
在 GameScene 渲染层中，添加陷阱渲染：
- ARMED 状态：在对应瓦片绘制微小的半透明标记（如 '∧' 或精灵图标）
- TRIGGERED/CAPTURED 状态：绘制明显的触发标记
- 玩家自己的陷阱用白色，未知陷阱用灰色
这样玩家能记住自己放了哪些陷阱。
```

**建议 2：扩大陷阱感知范围**
```
动物在移动到陷阱相邻格（3×3 范围）时就有概率检测到陷阱，
检测到后 fleeing/hunt/wander 时会主动避开该瓦片（视为不可通行）。
这样大型动物确实能"嗅到"陷阱并绕路，而非必须踩上去才知道。
```

**建议 3：陷阱老化递减**
```
陷阱放置时间越长，动物感知概率越低（气味消散）。
放置 < 1000 秒：100% 感知率；> 5000 秒：50%；> 8000 秒：25%。
```

## 5. 耐力系统

### 当前逻辑

```
maxFleeStamina = endurance × 30
每步消耗 = 2
速度加成 = speed × (1.0 + 0.5 × staminaRatio)
```

**优点**：
- 公式简洁，数值范围合理
- `getActionTime()` 重写实现动态速度

**问题**：

| # | 问题 | 严重度 |
|---|------|--------|
| 1 | **耐力没有恢复机制**——`endFleeing()` 直接将 fleeStamina 设为 -1，下次再逃跑时重新从满耐力开始。这意味动物每次逃跑都是"满血"逃跑，缺乏疲劳累积 | 中 |
| 2 | **耐力只用于逃跑**——WANDER/HUNT/GRAZE 状态下没有任何耐力概念 | 低 |

### 改进建议

**建议 1：疲劳累积**
```
Animal 添加一个 fatigue 字段（0-100）。
每次 endFleeing() 时，根据上次消耗的耐力比例增加 fatigue。
fatigue 影响：
  - 下次 maxFleeStamina = base × (1.0 - fatigue × 0.5)
  - fatigue 以 0.1/游戏分钟 的速度自然恢复
这防止动物被反复追逐后仍能满速逃跑。
```

## 6. 能量流动系统

### 当前逻辑

```
TRANSFER_RATE = 0.2（猎物 20% 能量转移给捕食者）
自然死亡：尸体分解 → EnergyFlowManager.recordNaturalDeath()
  → 50% 能量回流植被，50% 损耗（隐含在尸体 decay 中）
捕食：recordPredation() → max(20% prey energy, huntGain)
玩家击杀：recordPlayerKill() → 无能量转移，仅记录
迁徙：区块能量回流 ≥ 200 → 标记 foodRich → 概率生成捕食者
植被加成：boost = min(0.3, energy/1000)，每 tick 衰减 5%
```

**优点**：
- 能量流设计完整，符合生态学"十分之一定律"
- 尸体分解 → 植被加速 → 吸引更多草食动物的正向循环
- 迁徙机制让生态系统自驱动

**问题**：

| # | 问题 | 严重度 |
|---|------|--------|
| 1 | **玩家击杀的能量完全消失**——玩家杀死动物后，该动物的能量既不给捕食者也不回流植被，等于从生态系统中"蒸发"。长期大量狩猎会导致生态失衡 | 中 |
| 2 | **植被加成衰减过快**——5%/tick 的衰减意味着 13 tick 后只剩 50%，玩家很难感受到"这片土地因为尸体分解而更肥沃"的效果 | 低 |
| 3 | **迁徙生成只在每 100 回合检查**——如果玩家快速行动，可能 100 回合内生态已变化多次但迁徙没触发 | 低 |

### 改进建议

**建议 1：玩家击杀的部分能量回流**
```
玩家击杀时，动物尸体的 30% 能量回流到植被（低于自然死亡的 50%，
因为部分能量被作为战利品带走），70% 蒸发。
这保持生态系统不因玩家狩猎而崩溃。
```

**建议 2：可视化能量流（调试/交互）**
```
在调试模式下，在地图上显示每个区块的能量回流数值和植被加成。
让玩家理解"狩猎→尸体→肥沃土地→更多植物→更多动物"的循环。
```

## 7. 现实气泡

### 当前逻辑

```
半径 = 40 瓦片（曼哈顿距离）
气泡内：执行完整 AI 回合（while 循环消耗所有移动点）
气泡外：仅每 500 回合检查一次繁殖
AI 计算：后台线程（单线程池），ConcurrentLinkedQueue 变更队列
防重复：AtomicBoolean computingTurns 守护
```

**优点**：
- 异步 AI 不阻塞 EDT，帧率稳定
- 气泡外只检查繁殖，计算量极低
- Mutation Queue 模式线程安全

**问题**：

| # | 问题 | 严重度 |
|---|------|--------|
| 1 | **气泡边界突变**——玩家移动到气泡边缘时，原来活跃的生物突然"冻结"，玩家回头走几步又"解冻"。这种突变在交互上很突兀 | 中 |
| 2 | **40 瓦片半径对于 600×400 窗口可能不够**——600px 游戏区域 ÷ tileWidth ≈ 420px ≈ 约 30 瓦片可见。40 瓦片气泡刚好覆盖可见区域+一点缓冲，但动物可能在玩家看不到的地方跑出去 | 低 |
| 3 | **气泡外生物完全不移动**——500 回合才检查繁殖，中间完全不更新位置。这意味着如果玩家跑很远再回来，动物还在原地 | 中 |

### 改进建议

**建议 1：气泡边缘过渡带**
```
添加"过渡带"概念（30-40 瓦片）：
- 0-30 瓦片：完整 AI
- 30-40 瓦片：仅 WANDER/GRAZE（不 HUNT/FLEE），移动频率减半
- >40 瓦片：仅繁殖检查
这样动物不会在 40 瓦片处突然冻结。
```

**建议 2：气泡外简化模拟**
```
气泡外的动物每 100 回合（而非 500）执行一次简化回合：
随机移动 1 格或原地休息。
这样玩家远离一段时间回来时，动物有轻微位移，更自然。
```

## 8. CreatureGrid 空间索引

### 当前逻辑

```
数据结构：ConcurrentHashMap<Long, List<Creature>>
key = ((long)chunkX << 32) | (chunkY & 0xFFFFFFFFL)
chunkSize = 32 瓦片

操作：
  add/remove: O(1) — ConcurrentHashMap put/remove
  getAtTile: O(1) — 计算所属 chunk → 遍历 list
  getInRadius: O(可见区块数) — 曼哈顿距离枚举 chunk
  countSameSpeciesNearby: O(1) — 检查 9 个相邻 chunk
```

**优点**：
- 简单有效的空间哈希
- ConcurrentHashMap 保证线程安全
- move 操作只在跨区块时更新（减少不必要的哈希重计算）

**问题**：

| # | 问题 | 严重度 |
|---|------|--------|
| 1 | **chunk 内使用 List 而非更细的网格**——当某个 chunk 有大量生物时（比如迁徙后），`getAtTile` 和 `getAllAtTile` 需要遍历整个 List | 低 |
| 2 | **没有生物上限保护**——虽然密度限制在同物种 5 瓦片内 4 只，但不同物种可以无限叠加在同一个 tile | 低 |

### 改进建议

当前实现在游戏规模下性能足够，**无需改进**。  
如果未来生物数量达到数百级别，可以考虑 chunk 内再分 4×4 子网格。

## 9. 玩家初始装备

### 当前配置

```
武器：生锈小刀（+3）、石斧（+5）
种子：大麦×5、黑麦×5、土豆×5、豆类×5、芜菁×5
```

**问题**：

| # | 问题 | 严重度 |
|---|------|--------|
| 1 | **没有食物和水**——玩家一开始 80% 能量 + 100% 水分，但没有任何可直接消耗的物品。前几步如果遇到危险没有任何缓冲 | 高 |
| 2 | **没有材料**——没有纤维绳、树枝、石头等基础材料，玩家无法立即制作陷阱或篝火 | 中 |
| 3 | **石斧 + 小刀重复**——两个都是武器/工具，功能重叠 | 低 |

### 改进建议

**建议：新手友好起始包**
```
武器：生锈小刀 ×1（基础防身）
食物：罐头食品 ×2 或 黑莓 ×5（应急食物）
饮水：瓶装水 ×1（应急饮水）
材料：纤维绳 ×3、小树枝 ×5、石头 ×2（可立即制作陷阱/篝火）
种子：各 3 个（而非 5 个，给材料腾出负重）
```

## 10. NPC 系统架构

### 当前组件

| 组件 | 状态 | 说明 |
|------|------|------|
| NpcDefinition | ✅ 已定义 | JSON 模板 |
| NpcRegistry | ✅ 已实现 | 注册表 |
| NpcManager | ✅ 已实现 | 实例管理 |
| NpcAI | ✅ 已实现 | 状态机 |
| NpcSocial | ✅ 已实现 | 社交关系 |
| NpcInventory | ✅ 已实现 | 背包 |
| NpcRegion | ✅ 已实现 | 区域分配 |
| NpcNameGenerator | ✅ 已实现 | 姓名生成 |

**问题**：

| # | 问题 | 严重度 |
|---|------|--------|
| 1 | **NPC 没有实际出现在游戏中**——虽然有完整的架构，但 GameWorld 初始化中没有 NPC 生成逻辑，游戏内也没有 NPC 交互 UI | 高 |
| 2 | **NpcInteractionScreen 存在但无路由**——覆盖层已创建，但没有从游戏场景触发 NPC 交互的入口 | 高 |
| 3 | **NPC 与 Creature 共享基类但 AI 完全独立**——NPC 有自己的 AI 状态机，但与动物 AI 没有共享基础设施 | 低 |

### 改进建议

**建议 1：最小化 NPC 交互实现**
```
1. 在 GameWorld 初始化时，在玩家起始位置附近生成 1-2 个 NPC
2. 当玩家走到 NPC 相邻瓦片时，按 'E' 键弹出 NpcInteractionScreen
3. 交互菜单至少包含：
   - 对话（随机问候语）
   - 交易（NPC 出售基础物品，用 NpcInventory）
   - 告别
4. 在 HUD 中添加 NPC 名称悬浮显示（鼠标悬停或靠近时）
```

**建议 2：NPC 基础行为可见化**
```
让 NPC 在地图上有可见行为：
- 白天在固定路线巡逻（Region 内随机移动）
- 晚上回到"家"（Region 中心点）
- 玩家靠近时显示 NPC 名称和当前行为状态
```

## 11. 交互友好性综合评估

### 当前交互方式

| 操作 | 触发方式 | 友好度 |
|------|----------|--------|
| 移动 | 方向键/WASD | ⭐⭐⭐⭐⭐ 直观 |
| 攻击 | 靠近 + 快捷键 | ⭐⭐⭐ 需要知道快捷键 |
| 拾取 | 快捷键 | ⭐⭐⭐ 需要打开拾取菜单 |
| 丢弃 | 菜单操作 | ⭐⭐⭐ 步骤较多 |
| 合成 | 打开合成菜单 → 选择 → 确认 | ⭐⭐⭐ 流程合理但缺乏提示 |
| 种植 | 需要知道种子可以种 | ⭐⭐ 缺乏引导 |
| 陷阱 | 需要知道 SetSnareAction | ⭐⭐ 新手完全不知道存在 |
| 查看生物信息 | 无 | ⭐ 无法查看 |
| 查看物品信息 | 有（查看按钮） | ⭐⭐⭐ 需要进入菜单 |

### 核心改进建议（按优先级排序）

#### 🔴 P0：新手引导

```
问题：游戏没有任何教程或引导，玩家不知道可以做什么。
建议：
1. 添加 HelpOverlay（已有），在游戏首次启动时自动弹出
2. 列出基础操作：移动、攻击、拾取、丢弃
3. 第一天的游戏日志添加引导提示：
   - "按 [?] 查看帮助"
   - "按 [I] 打开物品栏"
   - "按 [C] 查看可合成的物品"
```
